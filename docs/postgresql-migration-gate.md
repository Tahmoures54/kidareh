# راه‌اندازی دیتابیس خالی Neon

از آنجا که هنوز داده‌ای برای انتقال وجود ندارد، هیچ ابزار یا فرایند انتقال SQLite لازم نیست. دیتابیس مقصد باید تازه و خالی باشد.

## مراحل

1. در Neon یک Project و یک database مستقل برای Kidareh ایجاد کنید.
2. آدرس pooled connection را با SSL دریافت کنید.
3. در Vercel برای محیط‌های Preview و Production متغیرهای زیر را تنظیم کنید:
   - `DATABASE_BACKEND=postgresql`
   - `DATABASE_URL` (Secret)
   - `SECRET_KEY` (حداقل ۳۲ بایت تصادفی)
   - اتصال Vercel Blob و وجود `BLOB_READ_WRITE_TOKEN`
4. ابتدا فقط Preview را با این تنظیمات Deploy کنید.
5. اجرای Alembic باید schema را از ابتدا بسازد؛ هیچ جدول یا رکورد قبلی نباید لازم باشد.
6. بررسی کنید `/api/health` پاسخ سالم بدهد.
7. مسیرهای ثبت‌نام، OTP، ایجاد فروشگاه، ایجاد آگهی، جست‌وجو، ذخیره تصویر و نشست کاربر را در Preview آزمایش کنید.
8. پس از موفقیت آزمون‌ها، Production را جداگانه تنظیم و Deploy کنید.

## نکات ایمنی

- هیچ‌گاه آدرس کامل دیتابیس یا رمز آن را در Issue، Commit یا پیام عمومی قرار ندهید.
- از اتصال pooled Neon برای runtime استفاده کنید.
- Migrationهای Alembic باید پیش از پذیرش ترافیک اجرا شوند.
- SQLite در runtime پشتیبانی نمی‌شود. تست‌های قدیمی تا زمان انتقال کامل به PostgreSQL از fixture موقت استفاده می‌کنند.
- این راهنما هیچ تغییری در متغیرهای Vercel یا دیتابیس زنده اعمال نمی‌کند.
